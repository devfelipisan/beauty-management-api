# PR-26.4.1 — Financial Decision Builder Integration

## Implementado

- `EvaluateAppointmentChangeFinancials` agora usa exclusivamente `BuildFinancialDecisionSnapshot`.
- Cancellation e no-show compartilham a mesma resolução financeira.
- Snapshot contém Deposit, Receivable e Payments elegíveis com identidade, valores e versões.
- Allocation de Payments é congelada de forma determinística por `received_at ASC, id ASC`.
- Fingerprint SHA-256 é calculado sobre conteúdo canônico, sem metadados transitórios.
- Validator diferencia snapshot adulterado (`INVALID`) de estado financeiro alterado (`STALE`).
- Validação de Payment utiliza `tenantId + paymentId + version`.

## Invariantes

- `READY` somente é produzido após o builder.
- `TRANSFER` continua bloqueado.
- Nenhum valor financeiro é aceito de Operations.
- Nenhum Payment é criado artificialmente para representar Deposit.
- Consumers financeiros permanecem bloqueados até qualification física completa.
