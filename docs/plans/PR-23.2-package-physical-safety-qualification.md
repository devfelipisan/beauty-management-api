# PR-23.2 — Package Physical Safety Qualification

## Objective

Provar no runtime `workerd` + D1 + Service Bindings que atribuição, consumo de pacote, replay, ACK-loss e reconciliação são idempotentes, atômicos, concorrentes e isolados por tenant.

## Baseline

`BaselinePR231 = PASS` para lint, typecheck, testes unitários, testes Workers e dry-run. O bloqueio anterior `PackageReadyForPayment` permanece até a suíte física deste PR passar.

## Physical Environment

A suíte dedicada usa `vitest.config.workers.mjs`, D1 com todas as migrations e os bindings reais Clinical → Billing → Operations. Não usa fake repository para as provas de concorrência.

## Proof Matrix

- Assignment: elegibilidade, CAS da appointment, auditoria e replay.
- Consumption: CAS de saldo, constraint `UNIQUE(tenant_id, session_id, type)`, nunca saldo negativo e uma unidade por sessão.
- Replay/ACK-loss: reentrega do mesmo evento, falha após entrega e `dispatchOutboxBatch` posterior.
- Atomicity: movimento, saldo, idempotência, auditoria e outbox não deixam estado parcial.
- E2E: appointment atribuída, snapshot da session, completion, consumo e timeline.
- Safety: package expirado/exaurido bloqueia nova atribuição/consumo; dois tenants não compartilham dados.

## PackageReadyForPayment

Só passa quando a matriz física e os gates de regressão retornarem `PASS`. Payment, Ledger, Receivable, refund, reservation e ajuste manual permanecem fora de escopo.

## Definition of Done

`test:package-concurrency`, `test:workers`, `test:unit`, lint, typecheck, dry-runs e `git diff --check` passam; o relatório registra contagens de sucesso/bloqueio, movimentos, replay, ACK-loss e isolamento.
