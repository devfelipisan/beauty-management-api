# PR-11.5 — Multi-Worker Runtime Harness

O comando reproduzível local é `npm run dev:workers`, com Operations como Worker primário e Clinical/Billing como secundários. Cada configuração mantém seu `name`, `main` e bindings próprios; o caller declara `CLINICAL_SERVICE` e `BILLING_SERVICE` pelos nomes exatos dos Workers alvo.

Clinical e Billing são `WorkerEntrypoint` e expõem os métodos RPC sem transportar entidades de domínio. Operations permanece object-style HTTP e mantém o endpoint Customer como vertical de qualificação. O harness não cria `POST /appointments`.

No ambiente atual, o Wrangler inicia os Workers, mas informa os bindings locais como `not connected`, mesmo no modo multi-config e em processos separados. Esse resultado é mantido como bloqueio físico; não é substituído por HTTP público nem por um mock declarado como qualificado.
